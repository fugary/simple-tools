# 音频对齐

## 提取与识别

用 ffprobe 读取时长、视频轨道、宽高、SAR、旋转及色彩信息。保留源文件和来源位置。RTF 在 macOS 可用 `textutil -convert txt`；其他格式使用合适的文本解析器，不执行文档内命令。

提取 16 kHz 单声道 PCM WAV，用 whisper.cpp 输出完整 JSON。示例中的路径必须替换为实际路径，使用参数数组或可靠的 shell 引用：

```bash
ffmpeg -i INPUT.mp4 -map 0:a:0 -vn -ar 16000 -ac 1 -c:a pcm_s16le audio16.wav
whisper-cli -m MODEL.bin -f audio16.wav -l en -ojf -osrt -of asr -dtw small.en -nfa
```

纯英文语音可使用 small.en；中英混合语音使用相应多语言模型。`-dtw` 名称要匹配模型架构。先检查本机 `--help`；某些 whisper.cpp 版本中 flash attention 与 DTW 不兼容，必须用 `-nfa`。检查日志中 DTW 实际启用，并抽查 token 的 `t_dtw`，不能把全部为 -1 的结果称作有效词级 DTW。

官方来源：
- FFmpeg：<https://ffmpeg.org/download.html>
- whisper.cpp：<https://github.com/ggml-org/whisper.cpp>
- GGML 模型：<https://huggingface.co/ggerganov/whisper.cpp>

下载需要连接/传输超时和有限重试；停滞时断点续传并核验官方摘要，终止被替代的本次下载进程。不要留下无限后台重试。模型、源码和日志记录实际版本；不要把历史摘要套到不同模型。

## 稿件与音频匹配

- 先解析成中英对和备注，允许英文或中文跨多行。空行、分隔线不等于语音边界；中文“注意……”及语法解释是提示，不是英文正文的翻译。
- 规范化只用于匹配：大小写、弯引号、数字读法、缩写展开（we’re/we are）、英美拼写（colour/color）、sb./sth. 与实际读法。输出仍保留用户稿件。
- Whisper token 可能是单词片段，先按原始文本重组单词，再做全文单调顺序对齐，保留每个原稿条目的匹配率、首词偏移和语音锚点。重复句必须按上下文和顺序区分，不能简单做全局最佳模糊搜索。
- 低匹配率、首词未匹配、时间倒退或很大的跳跃需要局部复核。可重识别对应音频片段，注意将片段时间加回全局偏移。未朗读的词义说明可挂到对应例句顶部；无法定位的正文单独报告，不均匀插值伪造语音时间。
- `t_dtw` 是注意力定位，不一定是精确起音。可结合波形/静音边界微调；阈值随背景噪声选择，不能把固定提前量或“最近静音结束”直接当作所有视频的真值。检查修正没有跨到前一个单词或句子。
- 如需检测静音：`ffmpeg -i audio16.wav -af silencedetect=noise=-42dB:d=0.12 -f null -`。这是干净语音的起点示例，不是强制参数。笑声、音乐、未识别声音应根据实际音频处理。
- 拆分后的英文片段、中文译文、备注仍需语义对应；拆分起点沿用实际词时间，不能按字符数或句长比例摊分。

## 连续显示

在统一时间精度上先舍入所有起点，再令 `end[i] = start[i+1]`，最后一条结束于视频末尾。ASS 为百分之一秒精度，允许最终端点与视频时长最多相差一百分之一秒。严格检查起点单调递增；量化后出现相同起点时应合并/重新拆分，不能强行加毫秒制造极短字幕。

核查很短片段和超长停留。学习用途允许在停顿中保持上一条，但镜头已经换到不相关内容时，应结合用户要求决定是否调整。不要把连续显示误写成字幕条目之间重叠。
